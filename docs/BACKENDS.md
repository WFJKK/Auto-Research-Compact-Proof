# Agent backends

The run config's `backend` picks where each round's response comes from. All four produce the same files in the round folder, so everything downstream (parsing, sandbox, checker, reports) is identical.

| Backend | Who answers | What it costs | Use it for |
| --- | --- | --- | --- |
| `fake` | files replayed in order | nothing | tests, baselines, dry runs |
| `manual` | you, pasting each prompt into claude.ai and saving the answer | nothing beyond your subscription | trying the loop by hand, a few rounds |
| `api` | the Messages API with an API key | per token (see `config/prices.yaml`) | unattended runs with full control of thinking and effort |
| `claude_code` | the official Claude Code CLI, headless, under your own Claude login | nothing per call; counts against the subscription's usage limits | unattended runs on a Pro or Max subscription |

## The `claude_code` backend

Each attempt runs the CLI as a plain model call: `claude -p --tools "" --output-format stream-json --verbose --no-session-persistence --setting-sources "" --disable-slash-commands --strict-mcp-config --model ... --effort ...`, with the prompt on stdin and an empty temporary folder as its working directory. With no tools, no project settings and no MCP servers it can only answer (not `--bare`, which would ignore a subscription login); it cannot read or write anything of the pipeline's. The streamed output holds every assistant message and a final result event. A long answer arrives as several assistant messages, because the CLI continues when one hits its output limit or when its stream is cut off, and the result event's own text holds only the last piece (which once lost the headings of a 68k-token answer); so the response is joined from all assistant messages, and the result event supplies the token counts. A cut falls in the middle of a line as often as not, and a resumed stream sometimes repeats a few characters from before the cut, so the pieces are concatenated exactly, and the repetition is dropped when that is what makes the recipe parse. (Three of the first twenty max2 rounds were lost to a join that put a newline at every cut; the pieces are kept in `response_raw.json`, so such a response can be joined again.) `ANTHROPIC_API_KEY` (and the pipeline's own key variable) are removed from the CLI's environment, so it can never fall back to billing an API key.

**One model per run.** When the requested model declines a request, the CLI by default asks another model and reports the swap only in its events and in the result's `modelUsage`. On 26 October 2026 a test call with the CLI's default system prompt got two refusals from Fable 5.1 and an answer from Opus 4.8; the pipeline's own system prompt got Fable's answer with no refusal. The backend sets `CLAUDE_CODE_NO_MODEL_FALLBACK=1` in the CLI's environment, so the CLI may not swap; an answer that still shows another model (a swap event, or another model's output in `modelUsage`) stops the run, and a refusal is recorded as one (`stop_reason: refusal`), which the loop counts (`max_consecutive_refusals`). Each round's meta records `models_used` (output tokens per model that answered), `safety_stops` and the CLI's model events.

Before a run starts, the loop checks that the CLI is installed and logged in (`claude auth status`). A usage or rate limit makes the loop wait and retry with growing waits (`api_retries` in the run config; `config/max2-pilot-subscription.yaml` waits up to 30 minutes between tries, since a subscription window can take hours to reset). If it still fails, the run stops cleanly and `resume` continues later without losing a round. A login problem stops the run at once.

Each round's `meta.json` records `cost_usd: 0` (nothing was billed) and `api_equivalent_usd`, the CLI's own estimate of what the same tokens would have cost on the API, so you can still see how much of your allowance a run consumed. When the CLI is signed in with an API key instead (`claude auth status` shows `"authMethod": "api_key"`; Claude Code's Console login, "Create an API key", which works where an organization blocks the Console's OAuth sign-in for Claude Code), the calls are billed and `api_equivalent_usd` is the bill.

**Terms.** Whether a subscription may be used for scripted, headless Claude Code runs is set by Anthropic's terms for Claude Code, which have changed during 2026. At the time of writing, signing in to the unmodified Claude Code binary with your own subscription counts as ordinary use, headless runs draw on the subscription's limits, and products built on the Agent SDK are expected to use an API key. Read the current policy for your own account before relying on this backend.

**Model names.** `agent_model` is passed to `--model`, which accepts either a full model name or an alias the CLI knows (such as `opus`). `effort` goes to `--effort` (`low`, `medium`, `high`, `xhigh`, `max`). `thinking` and `max_output_tokens` are API-only and ignored here; the CLI manages its own thinking.
